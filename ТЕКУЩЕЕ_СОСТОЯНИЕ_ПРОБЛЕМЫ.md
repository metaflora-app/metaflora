- Либо REST API кешируется браузером/Telegram

- Либо проблема в самом Telegram WebApp

### 2. Пользователь определяется как free вместо premium ❌
**Симптомы:**
- В Supabase таблице users: `subscription_type = 'premium'`
- Но мини-апп показывает все онбординг экраны (как для free)
- `getOrCreateUser()` возвращает `subscription_type: 'free'`

**Причина:**
- Та же проблема с кешем - возвращаются старые данные
- Или REST API запрос не работает правильно

## 🐛 РЕАЛЬНАЯ ПРОБЛЕМА:

**`getOrCreateUser()` ВСЕГДА возвращает баланс 0 вместо реального баланса из Supabase!**

### Проверено вручную:
1. ✅ SQL запрос в Supabase показывает правильный баланс (10000)
2. ✅ REST API через curl возвращает правильный баланс (10000)
3. ✅ UPDATE и INSERT работают вручную через SQL
4. ❌ НО в коде мини-аппа `getOrCreateUser()` возвращает баланс 0

### Возможные причины:

#### 1. Telegram WebApp кеширует fetch запросы
- Telegram может кешировать все HTTP запросы внутри WebApp
- Обычные заголовки Cache-Control не работают в Telegram

#### 2. Service Worker кеширует запросы
- Может быть установлен Service Worker который кеширует API запросы
- Нужно проверить и отключить

#### 3. Проблема с CORS или preflight запросами
- Браузер может делать preflight OPTIONS запрос
- Supabase может не отвечать правильно на OPTIONS

#### 4. Проблема с async/await в Telegram WebApp
- Telegram WebApp может не поддерживать async/await правильно
- Нужно использовать .then() вместо await

#### 5. Множественные запросы создают race condition
- Несколько компонентов вызывают getOrCreateUser() одновременно
- Первый запрос возвращает старые данные, последующие тоже
