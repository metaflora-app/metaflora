# покрытие моделей провайдерами

Отчёт строится из исполняемых маршрутов каталога, а не из названия карточки или логотипа. Поэтому он показывает фактическое состояние кода:

- `payable` — есть маршрут через активные Polza или KIE;
- `frozen` — маршрут есть только через замороженного провайдера;
- `beta` — модель находится в экспериментальном разделе;
- `unrouted` — карточка есть, но исполняемый маршрут для неё не задан.

Запуск отчёта:

```sh
node scripts/report-provider-coverage.js
```

`src/provider-model-snapshot.js` — снимок каталога Polza без ключей и других секретов. Сейчас в нём 388 подтверждённых провайдером моделей. Снимок хранит нормализованную цену, публичные `supportedParameters` и флаг `endpointAvailable`, но не сохраняет URL эндпоинта. Проверка через Railway сравнивает снимок с живым каталогом в обе стороны:

```sh
railway run node scripts/sync-polza-provider-models.js
```

У KIE нет открытого метода со списком всех моделей: документированный API позволяет проверить доступ и баланс, но не выгрузить полный каталог. Поэтому ID моделей KIE нельзя добавлять по догадке.

`unrouted` нельзя считать доступной моделью только потому, что её название встречается в каталоге поставщика. Перед публикацией ей нужен явный ID поставщика, контракт входных параметров и проверенный ответ API. Это защищает каталог от карточек, которые открываются, но не могут выполнить запрос.

Модели без числовой цены не попадают в оплачиваемые маршруты. Текущий публичный снимок даёт 360 исполняемых не-embedding/не-Sol Polza-записей, из них 359 имеют подтверждённую цену; `fish-audio/transcribe-1` остаётся недоступной, потому что провайдер отдаёт только валюту без числовой единицы тарификации. Снимок проверяется в экономическом аудите отдельно от пользовательского каталога, чтобы сырые записи провайдера не ломали карточки, иконки и промпт приветственного агента.
