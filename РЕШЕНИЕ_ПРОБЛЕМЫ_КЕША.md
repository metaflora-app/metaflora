## 🎯 ПРОБЛЕМА:

Telegram WebApp кеширует fetch запросы к Supabase REST API, из-за чего:
- `getOrCreateUser()` возвращает баланс 0 вместо 10000
- `getOrCreateUser()` возвращает subscription 'free' вместо 'premium'
- Все действия выдают "Недостаточно метакоинов"

Обычные методы борьбы с кешем (Cache-Control, timestamp) не работают в Telegram WebApp.

---

## 💡 РЕШЕНИЕ:

Создан API proxy на веб-сервисе (metaflora-service), который проксирует запросы к Supabase. Это обходит кеш Telegram WebApp.

### Архитектура:

```
Мини-апп (Telegram WebApp)
    ↓
API proxy (веб-сервис на Railway)
    ↓
Supabase (база данных)
```

## 🔧 API ENDPOINTS:

### 1. GET /api/user?telegram_id={id}

Получить пользователя по Telegram ID.

**Response:**
```json
{
  "id": "uuid",
  "telegram_id": 994500304,
  "subscription_type": "premium",
  "metacoins_balance": 10000,
  ...
}
```

Или `null` если пользователь не найден.

### 2. POST /api/user

Создать нового пользователя.

**Request:**
```json
{
  "telegram_id": 994500304,
  "username": "username",
  "first_name": "First",
  "last_name": "Last"
}
```

**Response:**
```json
{
  "id": "uuid",
  "telegram_id": 994500304,
  "subscription_type": "free",
  "metacoins_balance": 0,
  ...
}
```

### 3. POST /api/metacoins/purchase

Купить метакоины.

**Request:**
```json
{
  "user_id": "uuid",
  "amount": 5000
}
```

**Response:**
```json
{
  "success": true,
  "newBalance": 15000
}
```

### 4. POST /api/metacoins/spend

Списать метакоины за действие.

**Request:**
```json
{
  "user_id": "uuid",
  "cost": 50,
  "action_type": "analysis"
}
```

**Response:**
```json
{
  "success": true,
  "newBalance": 9950
}
```

Или при недостатке баланса:
```json
{
  "success": false,
  "error": "Insufficient balance",
  "currentBalance": 0,
  "required": 50
}
```

### 5. POST /api/subscription/purchase

Купить подписку.

**Request:**
```json
{
  "user_id": "uuid",
  "subscription_type": "premium",
  "months": 1
}
```

**Response:**
```json
{
  "success": true,
  "newBalance": 10150,
  "bonusMetacoins": 150
}
```

## 🔒 БЕЗОПАСНОСТЬ:

- Все API endpoints используют Supabase Anon Key (безопасно для клиента)
- RLS (Row Level Security) отключен для таблиц users и metacoins_transactions
- В будущем можно переключиться на Service Role Key на сервере для дополнительной безопасности

## 🔍 ЧТО БЫЛО ИЗМЕНЕНО В КОДЕ:

### До (прямые запросы к Supabase):

```typescript
// Прямой fetch к Supabase REST API
const response = await fetch(
  `${supabaseUrl}/rest/v1/users?telegram_id=eq.${telegramId}`,
  {
    headers: {
      'apikey': supabaseAnonKey,
      'Authorization': `Bearer ${supabaseAnonKey}`,
    },
  }
);
```

### После (через API proxy):

```typescript
// Запрос к API proxy на веб-сервисе
const response = await fetch(
  `${API_URL}/user?telegram_id=${telegramId}`,
  {
    method: 'GET',
    headers: {
      'Content-Type': 'application/json',
    },
  }
);
```
